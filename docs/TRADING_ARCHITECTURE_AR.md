# معمارية منصة التداول الذكية

## 1. الواجهة

- تسجيل دخول عربي RTL.
- جلسة إدارية منفصلة.
- خانة PIN/كلمة مرور ثانية لفتح لوحة التحكم الحساسة.
- زر تشغيل / إيقاف مؤقت / إيقاف طارئ.
- عرض حالة كل منصة، الرصيد، المراكز، الأوامر، PnL، المخاطر، وسجل قرارات الذكاء الاصطناعي.

## 2. خزنة الأسرار

لا تحفظ أي API key أو secret أو كلمة مرور داخل GitHub أو ملفات المصدر.

يجب استخدام خزنة أسرار مشفرة، مع تدوير المفاتيح، وإخفاء القيم في السجلات. يفضل أن تكون مفاتيح التداول بلا صلاحية سحب الأموال.

## 3. طبقة السوق

لكل رمز يتم جمع:

- OHLCV متعدد الأطر الزمنية.
- حجم التداول والسيولة.
- السبريد وعمق دفتر الأوامر عند توفره.
- بيانات الصفقات.
- حالة المنصة والاتصال.

تُوحّد البيانات قبل وصولها للاستراتيجيات حتى لا تختلف الوحدات بين المنصات.

## 4. طبقة الاستراتيجيات

كل استراتيجية لها:

- اسم وإصدار.
- إعدادات قابلة للتكرار.
- شروط دخول.
- شروط خروج.
- وقف خسارة.
- جني ربح / trailing stop عند الحاجة.
- حدود تعرض.
- نتائج backtest محفوظة.
- تاريخ التغييرات.

لا يتم اعتبار backtest دليلاً على الربح المستقبلي.

## 5. طبقة الذكاء الاصطناعي

الذكاء الاصطناعي يحلل السوق والاستراتيجيات والأخبار والبيانات المسموح بها ويولد **إشارة مفسرة**.

القاعدة الصارمة:

> الذكاء الاصطناعي لا يستطيع تجاوز Risk Engine، ولا يستطيع تغيير حدود المخاطر أو استخراج الأسرار أو تنفيذ أمر محظور.

يجب تسجيل المدخلات المختصرة، القرار، درجة الثقة، أسباب الرفض، والنتيجة اللاحقة للتقييم.

## 6. محرك المخاطر

قبل كل أمر:

1. فحص حالة النظام.
2. فحص الاتصال وصحة بيانات السوق.
3. فحص الرصيد والسيولة.
4. فحص حجم المركز والتعرض.
5. فحص الخسارة اليومية/الأسبوعية.
6. فحص عدد الأوامر ومعدل التكرار.
7. فحص الانزلاق السعري المتوقع.
8. فحص حدود الرمز والمنصة.
9. تطبيق Circuit Breaker عند أي خلل.

إذا فشل أي فحص: **لا يتم إرسال الأمر**.

## 7. التنفيذ

يتم فصل الإشارة عن التنفيذ. التنفيذ مسؤول عن idempotency، منع تكرار الأوامر، تتبع order ID، إعادة المحاولة الآمنة، والتعامل مع partial fills.

## 8. مصادر GitHub

سيتم الاعتماد فقط على مشاريع يمكن قانونياً دمجها أو تشغيلها كاعتماد خارجي. من المشاريع التي تم العثور عليها:

- `freqtrade/freqtrade` — GPL-3.0.
- `freqtrade/freqtrade-strategies` — مستودع استراتيجيات منفصل، ويجب فحص ترخيص كل ملف/استراتيجية قبل التوزيع.
- `hummingbot/hummingbot` — Apache-2.0.

لا يجوز تجميع «كل مشاريع التداول» آلياً في مستودع واحد؛ يجب أولاً فحص الترخيص، الاعتماديات، الأسرار، الثغرات، جودة الكود، واختبارات كل مشروع.

## 9. الاستضافة

لا يوجد وعد واقعي بخادم مجاني «مدى الحياة». يمكن إعداد خيارات مجانية/منخفضة التكلفة عندما تكون متاحة، لكن يجب أن تكون المنصة قابلة للتشغيل على VPS أو جهاز محلي أيضاً.

## 10. الهاتف

الواجهة ويب متجاوبة ويمكن فتحها من إنترنت الهاتف. يجب عدم تعريض واجهة الإدارة مباشرة للإنترنت دون HTTPS ومصادقة قوية وحدود محاولات وتدابير حماية مناسبة.

## 11. سياسة التشغيل

- Paper Trading أولاً.
- Live Trading مغلق افتراضياً.
- لا سحب أموال عبر مفاتيح البوت.
- إيقاف طارئ واضح.
- Kill switch مستقل عن الذكاء الاصطناعي.
- سجل تدقيق غير قابل للتلاعب بسهولة.
- تحديثات مثبتة الإصدار مع اختبار قبل التفعيل.
