# Autonomous Business Manager

نظام إدارة أعمال وأتمتة شخصي بواجهة عربية RTL، مبني على:

- FastAPI
- SQLite
- Playwright
- Python
- HTML / CSS / JavaScript
- تشفير الأسرار باستخدام Fernet
- نظام موافقات بشرية
- مراقبة الاتصال بالإنترنت
- حفظ جلسات المتصفح
- تحليل آمن للكود المرفوع
- إشعارات Telegram / WhatsApp Business API

---

## الهدف

إدارة المشاريع والمهام والأتمتة من واجهة واحدة.

النظام يستطيع:

1. إنشاء المشاريع.
2. حفظ المحادثات لكل مشروع.
3. إنشاء بطاقات عمل.
4. وضع المهام في قائمة انتظار.
5. طلب موافقة المستخدم قبل العمليات الحساسة.
6. تشغيل عمليات متصفح منظمة عبر Playwright.
7. حفظ جلسات المواقع.
8. اكتشاف انتهاء الجلسة.
9. إيقاف المهام عند انقطاع الإنترنت.
10. استئناف المهام بعد عودة الاتصال.
11. رفع الملفات وتحليل الكود بشكل ثابت.
12. حفظ الأسرار بشكل مشفر.
13. تسجيل الأحداث والعمليات في SQLite.
14. إرسال إشعارات عند الحاجة.

---

## واجهة النظام

الواجهة عربية RTL وبتصميم داكن حديث.

رسالة الترحيب:

`<°ارحب يا وجه النقاء>°`

وتحتوي الواجهة على:

- المشاريع
- المحادثة
- بطاقات العمل
- الموافقات
- المتصفح
- الملفات
- الأسرار
- الأحداث
- حالة النظام
- الإعدادات

---

## أنواع سير العمل

يدعم النظام عدة أنواع من سير العمل:

### API / Account

للعمل مع الحسابات وواجهات API المسموح بها.

### Upload / Design / POD

لإدارة الملفات والتصاميم وعمليات POD.

### Code + API

لتحليل الملفات البرمجية والتعامل مع APIs بطريقة منظمة وآمنة.

### Dual

يجمع بين عمليات المتصفح وعمليات API المنظمة.

## أمان المتصفح

يستخدم Playwright لتنفيذ عمليات المتصفح الطبيعية فقط.

العمليات المنظمة الحالية:

- `browser_open`
- `browser_navigate`
- `browser_click`
- `browser_fill`
- `browser_text`
- `wait`

لا يقوم النظام بـ:

- تجاوز CAPTCHA
- تجاوز أنظمة الحماية
- سرقة بيانات الدخول
- تخطي حدود الاستخدام
- انتحال بصمة المتصفح
- تشغيل JavaScript ضار
- تشغيل Shell من مدخلات المستخدم
- تشغيل Python مرفوع بشكل مباشر

---

## انقطاع الإنترنت

النظام يحتوي على مراقب اتصال مستقل.

عند انقطاع الإنترنت:

`ن؟`

يتم إيقاف المهام التي تعتمد على الاتصال.

وعند عودة الاتصال:

`>س✓<`

يمكن استئناف المهام المتوقفة.

---

## انتهاء جلسة الحساب

إذا انتهت جلسة الموقع، يتم إيقاف المهمة وعدم محاولة تجاوز تسجيل الدخول.

الإشعار:

`<|> [project number]`

ويحتاج المستخدم إلى إعادة المصادقة بالطريقة الطبيعية.

---

## الموافقات

العمليات الحساسة لا يتم تنفيذها تلقائياً بدون موافقة.

الحالات الرئيسية:

- `needs_approval`
- `queued`
- `running`
- `paused`
- `completed`
- `stopped`
- `error`

الإجراءات:

- Approve
- Reject
- Pause
- Stop
- Resume

---

## قاعدة البيانات

يستخدم النظام SQLite محلية.

الجداول الرئيسية:

- `projects`
- `chat_messages`
- `work_cards`
- `approvals`
- `browser_sessions`
- `secrets`
- `events`
- `uploaded_files`

قاعدة البيانات تستخدم:

- Foreign Keys
- WAL Mode
- Busy Timeout
- Migration بسيطة للجداول القديمة

---

## الأسرار

الأسرار الحساسة يجب ألا توضع داخل GitHub.

يتم استخدام:

- Fernet encryption
- PBKDF2
- Session tokens
- Hashing
- Secure comparison

يجب وضع مفاتيح API وكلمات المرور داخل البيئة أو لوحة الأسرار الآمنة.

---

## OpenAI

يمكن للنظام استخدام OpenAI بشكل اختياري.

إذا لم يتم وضع:

`OPENAI_API_KEY`

يستمر النظام باستخدام الاستجابات المحلية الأساسية.

لا تضع مفتاح OpenAI داخل الملفات أو GitHub.
